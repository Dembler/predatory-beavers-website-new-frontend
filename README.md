# Хищные Бобры — frontend

Frontend БК ВГУ «Хищные Бобры» на Vue 3, Vite и Node.js. Клубная navy/red палитра,
компактная навигация и адаптивные страницы команд, турниров и истории клуба.

## Запуск

```cmd
copy .env.example .env
npm install
npm run dev
```

Сайт откроется на `http://localhost:5173` и на `http://<локальный-IP>:5173`.
Backend ожидается на `http://localhost:8000`; запросы `/api` и `/media` проксируются через Vite.
Для доступа с другого устройства оно должно находиться в той же сети, а порт `5173` должен быть разрешён в брандмауэре.

## Команды

```cmd
npm run lint:ci
npm run format:check
npm run type-check
npm run build
```

В ограниченной Windows-среде используйте `npm.cmd run dev -- --host 127.0.0.1 --configLoader native`.
Сборка в этой среде: `npm.cmd run type-check`, затем `npm.cmd run build-only -- --configLoader native`.

## Управление сайтом

Админка находится по адресу `/admin`; ссылка также есть в подвале. Доступ имеют роли ADMIN и EDITOR.
Она позволяет создавать, изменять и удалять игроков, матчи, турниры и залы, загружать фотографии,
редактировать их описания, публиковать историю клуба и правила. Неопубликованные записи скрыты
с публичных страниц. Текст сохраняется как обычный текст; HTML не исполняется.

Первичная локальная настройка выполняется в каталоге backend:

```powershell
.venv/Scripts/python.exe scripts/setup_local.py --apply --serve
```

При первом запуске backend создаёт игнорируемую рабочую `data/local.db` из исходного снимка;
перед миграцией делает резервную копию. Если активного администратора нет, создаётся
учётная запись со случайным паролем; данные входа находятся в игнорируемом Git файле
`data/local-admin-credentials.json` в каталоге backend.
При повторном запуске существующий пароль сохраняется. Не публикуйте этот файл.

Правила включают схему бросков и короткую викторину. Расписание поддерживает фильтры команд
и статусов, московское время, отдельные блоки ближайших игр и результатов.

Уменьшенные WebP-копии клубных фото и эмблемы воспроизводятся через
`python scripts/optimize_images.py` с Pillow. Исходники и сохранённые варианты оформления
находятся в `assets/source-images`, вне публичной сборки. Размеры и контрольные суммы
перечислены в `public/images/optimized-manifest.json`.

Шрифты загружаются локально в WOFF2. TTF и лицензии сохранены в `assets/source-fonts`;
генерация — `python scripts/optimize_fonts.py` с необязательным инструментом `fonttools[woff]`.
Кириллица и исходные начертания сохранены.

Основные DTO в `src/shared/types.ts` берутся из сгенерированного OpenAPI-контракта.
После изменения backend выполните `npm run api:generate -- http://127.0.0.1:8000/openapi.json`
или передайте путь к сохранённому OpenAPI JSON вместо URL, затем `npm run type-check`.
Запускайте генерацию от актуальной версии API; файл `src/shared/api/schema.d.ts` хранится в Git.

В админке есть отдельные разделы команд и редакционных достижений, поиск и фильтры,
визуальный выбор фото и ссылки на места использования. Черновик возвращается после
повторного входа в тот же аккаунт. Изменение устаревшей записи показывает конфликт,
а повтор создания после потери ответа использует тот же ключ операции.
Удалённые записи и фотографии доступны в корзине соответствующего раздела. Восстановление
возвращает их скрытыми: перед публикацией редактор проверяет содержимое и зависимости.
Для этого требуются актуальный backend и миграции 0015–0018; перед обновлением сохраните
резервную копию БД и медиатеки. Настройка HTTPS-развёртывания описана в backend.

Пример конфигурации для HTTPS reverse proxy — `deploy/nginx.conf.example`: он обслуживает
собранный `dist-prerender` (либо `dist` для обычной SPA), проксирует API/медиа на локальный backend, задаёт CSP и ограничивает
попытки входа. Укажите свой домен, пути сертификатов и сборки; проверьте `nginx -t`
перед включением. Пример рассчитан на общий origin сайта и API.

Официальная заявка АСБ и редакционные клубные профили показаны раздельно на страницах команд.
Профиль АСБ открывается по `/teams/{men|women}/players/{id}`, клубный — по
`/players/local/{id}`. Старые ссылки `/players/{id}?team=men|women` перенаправляются
в АСБ, без `team` — в клубный профиль. Форма UUID не определяет источник данных.

## Публичный HTML, поиск и превью ссылок

Обычный `npm run build` сохраняет быструю SPA-сборку в `dist`. Для рабочего сайта
можно отдельно собрать готовый HTML публичных страниц:

```powershell
npx playwright install chromium
$env:PRERENDER_SITE_URL = 'https://club.example'
$env:PRERENDER_API_URL = 'http://127.0.0.1:8000'
npm run build:prerender
```

`PRERENDER_SITE_URL` — обязательный HTTPS origin рабочего сайта без пути;
`PRERENDER_API_URL` — обязательный доверенный origin API, доступный **со сборочного
сервера**. Это не адрес API в браузере. Production reverse proxy должен обслуживать
сайт и API на одном публичном origin. Не задавайте `VITE_API_BASE_URL` адресом
внутреннего сервера: относительные `/api` и `/media` должны работать через proxy.
Опциональный `VITE_SITE_URL` должен совпадать с `PRERENDER_SITE_URL`.

Команда проверяет типы, собирает Vite во временную папку и запускает изолированный
анонимный Chromium. Она читает только публичные GET API; cookies, авторизация,
административные API и локальные учётные данные не используются. Исходящие запросы
к внешним картинкам и картам во время сборки блокируются. Снимок содержит обычные
адреса изображений: посетитель загрузит их при просмотре.

Готовый каталог — `dist-prerender`: содержательный HTML, уникальные title/description,
Open Graph/Twitter, абсолютный canonical, `sitemap.xml` и `robots.txt`. Помимо восьми
основных страниц обнаруживаются все опубликованные локальные профили и игроки
текущей опубликованной заявки АСБ. Черновики и старые заявки не включаются. По умолчанию
разрешено до 500 маршрутов; `PRERENDER_MAX_ROUTES` явно увеличивает лимит (максимум
5000). `PRERENDER_TIMEOUT_MS` задаёт ожидание одной страницы: 45000 по умолчанию,
максимум 180000. Для установленного Edge можно задать
`PRERENDER_BROWSER_CHANNEL=msedge` вместо установки Chromium.

Готовность определяется завершением загрузчиков Vue и применением данных в DOM.
Ошибки API, неполная пагинация, оставшийся индикатор загрузки и ошибки JavaScript
останавливают сборку. Предыдущий `dist-prerender` при этом сохраняется. Публикуйте
полностью проверенный каталог атомарно; не копируйте частичные временные файлы.
Админка не рендерится: её отдельный shell сразу содержит `noindex`. Запрос неизвестного
или ещё не собранного маршрута получает `spa.html` с `noindex`, а не HTML главной.
Пример Nginx учитывает обе ситуации. Статические документы следует перепроверять,
поэтому HTML отдаётся без длительного кеширования; хешированные assets кешируются год.
`robots.txt` разрешает прочитать эти shell-страницы, чтобы робот увидел `noindex`:
запрет обхода сам по себе [не исключает URL из поиска](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

Это снимки опубликованных данных **на момент сборки**. После публикации, удаления
или скрытия материала запускайте сборку и атомарное обновление снова. Команда
`npm run refresh:prerender` проверяет все новые HTML до замены артефакта и сохраняет
предыдущий результат; `npm run refresh:prerender -- --watch` повторяет этот цикл каждые
пять минут. Блокировка исключает одновременные refresh, ошибка API или проверки
оставляет предыдущий результат. [Интервал, состояние, восстановление и systemd timer](deploy/prerender-refresh.md).
Без регулярного успешного обновления поисковики и пользователи без JavaScript
будут видеть старый снимок. Клиент Vue после запуска заменяет статический DOM,
получает свежие данные и сохраняет интерактивность. Пререндер не заменяет live API
и не обещает SSR-гидрацию. Скрипт не развёртывает сайт автоматически.

Проверки границ, анонимных запросов и завершения загрузки в Chromium:
`npm run test:prerender`. После сборки `npm run verify:prerender` проверяет каждую
готовую страницу с отключённым JavaScript, sitemap, shell админки и неизвестный маршрут.

## Правила оформления

- Использовать общую тему из `src/styles/theme.css`, не создавать отдельный CSS-файл для каждой страницы.
- Сохранять `#042A4E`, `#CB1914`, белый и светлый ice-фон как основные цвета.
- Исходные изображения и эксперименты хранить в `assets/source-images`, в `public` — только используемые ресурсы.
- Сохранять узнаваемость клуба, улучшая читаемость и предсказуемость интерфейса.
