# Firefox и WebKit — 8 ноября 2026

Статус: проверки завершены. Исправлен возврат фокуса мобильного меню; устранён
предел размера снимков длинных страниц. WebKit: 222 уникальных успешных сценария
с учётом профиля окна, 10 явных пропусков; Firefox: 3 ограниченные проверки;
Chromium: 8 проверок гонок редактора. Повторы не прибавлены к уникальному покрытию.

## Среда и безопасность данных

- Windows, Node 24.14.0, Playwright 1.64.1. Установлены Playwright Firefox 157.0
  (revision 1555) и WebKit 27.2 (revision 2370).
- Проверялся production `dist`, созданный `npm run build`, через Vite preview
  `http://127.0.0.1:4188`, с отдельным API на `127.0.0.1:8018`.
- Реальные операции редактора разрешены только после проверки защищённого маркера
  через preview и напрямую: обе проверки подтверждают `isolated=true` и точные пути
  отдельной `backend/data/e2e-browsers-20261108/e2e.db` и её медиатеки.
- База и медиатека подготовлены существующим `setup_e2e.py` через локальную обёртку.
  Миграции тестовой БД доведены до `0018`. Клубные записи в рабочей БД эти сценарии
  не создают и не редактируют.
- Пароли, runtime JSON, машинные отчёты и снимки остаются в игнорируемых каталогах.
  Trace и video отключены. При недоступности сервера тестовый guard теперь выдаёт
  короткую ошибку без заголовка с runtime token.

WebKit на Windows и профиль iPhone 13 не являются проверкой выпущенного Safari
на macOS/iOS или настоящего телефона. Firefox запускается в поставке Playwright.
В конфигурации Firefox предусмотрен настольный проект: Playwright не поддерживает
его `isMobile`. Финальный короткий запуск Firefox отдельно проверил ширины 1440 и
390 пикселей; это не эмуляция Firefox на Android.

## Изменения в проверках

- `E2E_BROWSER=chromium|firefox|webkit` выбирает движок. По умолчанию сохранён
  Chromium; имена проектов `desktop`/`mobile` сохранены для сценариев по размеру экрана.
- `E2E_ARTIFACTS_DIR` разделяет JSON, HTML и тестовые файлы разных запусков.
  Снимки корзины также перенесены в `testInfo.outputPath`, чтобы браузеры не заменяли
  доказательства друг друга.
- Уточнена инструкция: защищённый backend marker требует basename `e2e.db`.
  Независимые серверы нужно разделять каталогами, сохраняя это имя файла.
- Добавлен общий сценарий открытия меню команд через Enter, выбора обеих команд,
  закрытия после перехода и закрытия через Escape.
- Полные снимки публичных страниц сохраняются с `scale: 'css'`: на длинной странице
  состава при iPhone DPR=3 WebKit превышал предел 32767 пикселей. Полный контент
  сохраняется; проверки ширины, положения заголовка и ошибок JavaScript не изменены.
- К полному снимку диалога восстановления добавлен отдельный снимок viewport, чтобы
  проверять fixed-элементы после прокрутки без искажений склейки fullPage.

## Найденный дефект мобильного меню

После Escape в мобильном меню WebKit не возвращал фокус к кнопке открытия. Обход
внутри диалога работал, но `document.activeElement` после закрытия не был кнопкой.
В `App.vue` открытие через обе кнопки теперь явно фокусирует нажатую кнопку перед
`showModal()`. Это даёт нативному диалогу сохранённую точку возврата и не зависит от
автоматического фокуса кнопки при pointer click в браузере.

После production-пересборки проверены возврат к верхней кнопке после Escape,
возврат к нижней кнопке после закрытия, переход в команду девушек и закрытие при
расширении окна. Вместе с двумя длинными страницами команд: **3 passed, 0 failed**
в `.data/quality-browsers-20261108/webkit-fixes/playwright-results.json`.

## Нативный Tab в WebKit Windows

Первый настольный прогон подтвердил 50 сценариев, затем остановился на проверке
обхода ссылок меню клавишей Tab. Диагностика воспроизвела тот же результат на
минимальном HTML без кода и стилей сайта: `button → a → button` переводит фокус
с первой кнопки на последнюю. `Alt+Tab` в этой Windows-сборке также пропускает ссылку.
Это не свидетельствует об ошибке обработчика меню сайта.

Для контекста: зависимость обхода ссылок от настроек WebKit и рекомендация Option+Tab
описаны в [обсуждении разработчиков Playwright](https://github.com/microsoft/playwright/issues/5609).
Поведение текущей Windows-сборки проверено отдельно; рекомендация Option+Tab его
здесь не исправила.

Тесты используют проверку возможности на отдельной минимальной странице. Только
сценарий нативного Tab по меню получает явный skip при отсутствии этой возможности.
Функциональный сценарий меню продолжает выполняться. В сценарии карты пропускаются
только соответствующие утверждения о Tab к ссылке маршрута; ограничение записывается
в annotations. Axe, inert/aria-hidden, активация и выключение iframe, клавиатурный
вход в активный iframe и смена зала сохраняются.

Диагностика: `.data/quality-browsers-20261108/webkit-focus-diagnostic.json`.
Это ограничение покрытия; полный обход ссылок клавиатурой в настоящем Safari ещё нужен.

Уникальное покрытие WebKit вычислено по ключу **проект + файл + название сценария**,
с последним результатом каждого сценария. Итого: **222 passed, 10 skipped**:

- desktop: 112 passed, 4 skipped;
- mobile: 110 passed, 6 skipped;
- административные: 50 passed (прежние 42 и новые 8);
- публичные, включая профили: 172 passed, 10 skipped.

Это объединение нескольких прогонов, а не один безошибочный полный запуск.
Девять пропусков относятся к сценарию для другого профиля окна или к повторяющемуся
полному перебору ширин; один — к измеренному ограничению нативного Tab по ссылкам.
Пропусков из-за max-failures в финальном покрытии нет: все 35 оставшихся сценариев
действительно запускались. Проверка `--list`, первоначально записавшая пустой отчёт
этой выборки, в результат не включена.

Сводка с происхождением каждого результата:
`.data/quality-browsers-20261108/webkit-coverage-summary.json`.
Восемь Chromium-проверок и три Firefox-проверки не прибавлены к числу WebKit.

### Причины исходных трёх сбоев

1. Мобильное меню: подтверждённый дефект возврата фокуса. Исправлен в `App.vue`,
   повтор полностью прошёл с исходными проверками фокуса, закрытия и перехода.
2. Мужская команда и команда девушек: WebKit отказался создавать fullPage-снимки
   выше 32767 физических пикселей при DPR=3. Утверждения о runtime, ширине и
   заголовке до снимка проходили. `scale: 'css'` сохраняет полный контент; обе страницы
   повторно прошли без ослабления функциональных проверок.

Исходный полный запуск сохранён в `webkit-final`, исправленные сценарии — в
`webkit-fixes`. Более ранняя диагностическая попытка `webkit-desktop` отдельно
содержит неверно названную мной тестовую БД (backend marker безопасно запретил
операции) и ограничение Tab. Ошибки локаторов первого запуска новых гонок
`webkit-admin-final` также исправлены в тесте и не выдаются за продуктовые дефекты.

### Единичные таймауты WebKit

В повторе прежней админки настольный сценарий отказа восстановления остановился
на `locator.click`: браузер ожидал visible/enabled/stable у кнопки «Восстановить».
В новых гонках аналогично остановился один настольный сценарий сохранения свежих
правок после подтверждения reload. Соответствующие повторы без изменений прошли;
для восстановления — 4,1 с выполнения сценария. `force`, подмена клика и увеличение
локальных ожиданий ради прохождения не использовались. В CSS диалога нет постоянной
анимации, `reducedMotion=reduce` уже включён. Причина нестабильности не установлена;
это ограничение воспроизводимости, а не доказательство исправленного дефекта сайта.

### Firefox: точный объём

Финальный запуск имел общий предел 180 с и завершился за 23,6 с без принудительного
завершения процесса. Проверены реальные API и UI на изолированной production-сборке:

- календарь из 175 записей, страница по 24, переход на вторую страницу и Back;
- фильтр «Завершён», отсутствие скачивания сырых `/matches` и `/results-archive`;
- отсутствие горизонтальной прокрутки календаря при 1440 и 390 пикселях;
- отображение таблицы и её title, без горизонтального переполнения;
- реальный вход, сохранение сессии после reload, выход и 401 для анонимного admin API;
- отсутствие `pageerror` во всём коротком запуске.

Отчёт и снимки: `.data/quality-browsers-20261108/firefox-priority/diagnostic.json`.
Полный Firefox E2E не заявляется: ранние попытки полного набора прерывались при
создании/закрытии контекстов. Короткая проверка использует один контекст и повторно
использует страницу. В ранний момент диагностики свободная физическая память
Windows составляла около 600 МБ из 8 ГБ; причинная связь с таймаутами не доказана.

### Диалог и завершение серверов

Дополнительно просмотрены desktop и mobile `trash-confirmation-viewport.png` в
`webkit-admin-regression/test-results/admin-workflows-trash-rest-…`.
Мобильный viewport 390×664 (DPR=3): фон затемнён целиком, текст и обе кнопки видны,
фокус «Отмена», skip-link не показана. Полоса fixed-header посреди прежнего fullPage
была артефактом склейки после прокрутки, а не перекрытием интерфейса в viewport.

Тестовые API `8018` и preview `4188` остановлены через создавшие их сессии после
проверок. Проверка слушающих портов подтвердила их отсутствие. Рабочие `8000` и
`5173` оставлены запущенными. Изолированная БД, медиатека и все артефакты сохранены
в игнорируемых каталогах; коммиты и push не выполнялись.

Артефакты запусков лежат под `.data/quality-browsers-20261108/`:
`webkit-targeted-final`, `webkit-final`, `webkit-fixes`, `webkit-admin-regression`,
`webkit-admin-retry`, `webkit-mobile-remainder`, `webkit-editor-races`,
`webkit-editor-races-retry`, `chromium-editor-races`, `firefox-priority`.

## Повтор запуска

После запуска отдельного API/preview и проверки соответствия runtime JSON:

```powershell
$env:E2E_BROWSER='webkit'
$env:E2E_BASE_URL='http://127.0.0.1:4188'
$env:E2E_RUNTIME_FILE='../predatory-beavers-website-new-backend/data/e2e-browsers-20261108/e2e-credentials.json'
$env:E2E_ARTIFACTS_DIR='.data/quality-browsers-20261108/webkit-final'
npx.cmd playwright test --timeout=90000
```

В этом цикле общий лимит теста увеличен до 90 секунд через CLI для медленной
Windows-среды; локальные ограничения отдельных сценариев и ожиданий не ослаблены.
Для Firefox нужно заменить `E2E_BROWSER` и каталог артефактов. Подробная инструкция:
[tests/e2e/README.md](../tests/e2e/README.md).
