# Исправления по аудиту — 7 ноября 2026

Это отчёт первого цикла. Актуальное продолжение —
[серверный календарь, корзина и публичный HTML](quality-next-20261107.md).
Оно закрывает перечисленные ниже ограничения по загрузке архива, восстановлению
удалённых записей и HTML для поисковых роботов.

Проверены актуальные исходные коммиты frontend `5bee82b` и backend `2eafa65`, затем
исправления в обеих рабочих копиях. Код не закоммичен и не развёрнут. Рабочая база клуба
не изменялась: browser CRUD выполнялся на отдельной копии `e2e.db` с отдельной медиатекой,
одноразовым администратором и проверкой защищённого маркера тестового API.

## Проверки

- Production Playwright: публичные сценарии **156 passed, 8 skipped, 0 failed**;
  административные — **34 passed, 0 failed**, Chromium desktop и mobile.
  После последних изменений подписей, обработки ошибок и порядка матчей дополнительно
  прошли **16 административных + 2 публичных сценария восстановления после сбоя API**.
- Backend: полный pytest **140 passed**. Последние изменения дополнительно проверены
  **23 editor reliability + 9 match/club service** сценариями; эти результаты пересекаются
  с полным набором, их нельзя суммировать как уникальные тесты.
- Frontend ESLint, Prettier, TypeScript и production build прошли; backend Ruff,
  форматирование, mypy (124 файла), чистые миграции до 0017 и `alembic check` прошли.
- Визуальная проверка админки: 14 состояний на 1440 и 390 px, 12 Axe-сканов;
  нет найденных нарушений в этих сканах, горизонтального переполнения, JS-ошибок
  и битых видимых изображений. В публичном наборе нет serious/critical Axe-нарушений.
- Дополнительный браузерный проход с CSP из примера nginx: главная, клуб, команда
  и контакты на двух размерах — без зарегистрированных CSP-нарушений и JS-ошибок.
- `npm audit`: **0 известных уязвимостей**, включая зависимости инструментов.
- `docker compose -f compose.production.yaml config --quiet` принял конфигурацию.
  Контейнеры и реальный HTTPS-прокси в рамках этой проверки не развёртывались.

Проверки выполнялись совместно профильными агентами. Независимая команда OpenCode
перечитала исправления; её замечания о поиске, связях UI/API, внешних идентификаторах
и обработке неопределённого результата записи были перепроверены и устранены.

## Границы результата и дальнейшая работа

- Миграции **0015–0017** проверены на тестовых базах. Для рабочего запуска нужно
  сохранить резервную копию БД и медиатеки, применить миграции и перезапустить API.
  Инструкция по контракту и production — в backend `docs/editor-api.md`.
- Ранее публичные изображения оставлены совместимыми. Уже скачанные браузером/CDN
  копии невозможно отозвать удалением связи. Отменённые новые загрузки остаются
  приватными в медиатеке; автоматической очистки по TTL пока нет.
- Метаданные страниц и игроков обновляются в SPA. Отдельного SSR/предрендера для
  ботов социальных сетей пока нет.
- Объединённый публичный календарь/архив всё ещё использует полную загрузку истории
  перед клиентскими фильтрами. Для большого роста архива нужна общая серверная
  пагинация с сохранением нынешней логики источников.
- История правок и восстановление удалённых записей пока не представлены в UI;
  часть функций отображения матчей по-прежнему требует дальнейшего объединения.
- Реальные Safari/Firefox, пользовательское исследование со штатными редакторами
  и конфигурация действующего production-сервера в этот локальный прогон не входили.

Оценка после исправлений: frontend **7,5/10**, админка **7,5/10**. Это инженерная
оценка текущих сценариев, а не сертификат безопасности или обещание отсутствия багов.
