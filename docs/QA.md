# Проверка сайта — 31 октября 2026

Проверка следующего этапа описана в [mobile-ux.md](mobile-ux.md); ниже сохранён отчёт от 31 октября.

Проверка выполнена на production preview `http://127.0.0.1:4173`, без HMR и изменений исходников приложения во время заключительного прогона. Браузер: совместимый с установленной версией Playwright Chromium. Проекты: desktop 1440 × 1000 и mobile с параметрами iPhone 13.

Подтверждены все **54 применимых сценария**, ещё две проверки меню пропущены в неподходящем проекте устройства. Полный запуск занял 8 минут 18 секунд: 51 passed, 2 skipped, 3 failures в тестовом коде. После исправления селектора `select` и ожидания видимости dropdown все три оставшихся сценария прошли отдельный повтор за 34 секунды. Приложение между этими запусками не менялось. Неисправленных продуктовых ошибок этот прогон не выявил.

Все 20 административных сценариев на desktop/mobile прошли в полном запуске, включая реальные CRUD, публикацию CMS, загрузки файлов, CSRF, восстановление сессии и сетевые сбои. Axe не обнаружил serious/critical нарушений на восьми страницах, в редакторе и на расписании из 104 матчей в обоих проектах. Это результат автоматической проверки заданных сценариев, а не утверждение об отсутствии любых возможных ошибок.

Административные изменения выполняются только против копии `data/e2e.db` и отдельной `data/e2e-media`. Перед любым CRUD набор проверяет секретный маркер изолированного API напрямую и через фактический frontend proxy, сверяет пути базы и фото и блокирует запросы к другим API origins. Исходная база не используется. Пароли, runtime token, cookies и session state не записываются в отслеживаемые файлы; trace/video отключены. Созданные записи удаляются после сценария в обратном порядке зависимостей.

## Воспроизведение

Подготовка backend описана в `tests/e2e/README.md`. После запуска изолированного API и preview:

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:4173'
npm.cmd run test:e2e
```

Заключительный набор содержит 56 проверок в двух браузерных проектах; две проверки меню применимы только к своему виду устройства и пропускаются в другом проекте. Текущий отчёт: `.data/playwright-report/index.html`; машинный результат: `.data/playwright-results.json`; скриншоты: `.data/test-results/`.

Сохранённые результаты проверки:

- Полный запуск: `.data/qa-final-full/playwright-report/index.html` и `.data/qa-final-full/playwright-results.json`.
- Зелёный повтор исправленных сценариев: `.data/qa-final-targeted/playwright-report/index.html` и `.data/qa-final-targeted/playwright-results.json`.
- Десять отобранных скриншотов без паролей: `.data/qa-final-screenshots/` — главная, матчи, состав, правила, админка и редактор на desktop/mobile. Скриншоты просмотрены вручную; мобильные названия команд читаются полностью, заголовки не скрыты шапкой, формы и карточки не выходят за viewport.

ESLint, Prettier и отдельная TypeScript-проверка Playwright конфигурации и тестов завершились успешно.

## Покрытие

- Вход с ошибкой, восстановление сессии после reload, выход, отсутствие доступа без авторизации, возврат к форме входа при 401 во время сохранения.
- Создание, изменение и удаление игрока; действительная PNG загрузка, профиль на публичном сайте, запрет удаления используемого изображения и успешное удаление после снятия ссылки.
- Новые турнир и зал сразу доступны в редакторе матча; CRUD матча; очки обеих команд обязательны для завершённого матча; ничья отклоняется; обновлённый результат виден в расписании.
- История и правила: черновик закрыт для публики, публикация и изменение отражаются на публичной странице, удаление убирает раздел, HTML отображается текстом и не исполняется.
- Медиатека: запрещённый тип и превышение 8 МБ отклоняются; загрузка, изменение alt description и удаление работают.
- Две параллельные загрузки логотипов после reload используют один CSRF запрос; сохранение заблокировано, пока задержанная вторая загрузка не завершилась.
- Ошибка сети сохраняет введённые данные, повторная попытка создаёт ровно одну запись; публичная кнопка повтора восстанавливает список без reload.
- Запоздавший ответ мужского состава не перезаписывает уже загруженный женский состав. Гонка воспроизводится управляемыми барьерами, без фиксированных задержек.
- Пагинированное расписание из 104 матчей загружает обе страницы; фильтры команды и статуса сочетаются; победа клуба в гостях определяется правильно; фиктивный счёт scheduled матча скрыт; отменённые игры выделены в изменения расписания.
- Все публичные маршруты, 404 и login page: заголовок виден ниже фиксированной шапки, горизонтального переполнения и необработанных браузерных исключений нет; созданы desktop/mobile скриншоты и замеры навигации.
- Неизвестные и некорректные player IDs дают полезное сообщение и рабочую ссылку возврата к составу.
- Мобильное меню открывается и закрывается после перехода. Desktop dropdown согласован с `aria-expanded`, закрывается Escape/повторным кликом и корректно проходит Tab-навигацию.
- Интерактивные зоны бросков меняют очки и схему; викторина проходит четыре вопроса, не позволяет повторное начисление за ответ, показывает результат и сбрасывается.
- Axe WCAG 2 A/AA и 2.1 AA проверяет серьёзные/критические нарушения на восьми страницах, в редакторе и на объёмном mock расписании. Исключена только сторонняя devtools панель Vite, отсутствующая в production.

Автоматический набор не заменяет проверку экранным диктором, реальный Safari/Firefox и нагрузочный тест production инфраструктуры. Времена навигации привязаны к этому ноутбуку и локальному серверу, поэтому не используются как универсальный performance benchmark.
