# Второй цикл исправлений — 7 ноября 2026

Продолжение [первого цикла](quality-fixes-20261107.md). Проверены актуальные рабочие

## Календарь и архив

- Добавлен общий `/api/v1/calendar`. Фильтры команды, дисциплины, статуса и сезона,
  удаление дублей, подсчёт разделов и пагинация выполняются на сервере. Браузер
  получает до 24 записей вместо полной истории; ORM загружает только текущую страницу.
- Редакционный календарь имеет приоритет над соответствующей архивной записью.
  Скрытый или удалённый матч не подавляет самостоятельную опубликованную запись архива.
- Страница, фильтры и момент классификации `at` сохраняются в URL. Время фиксирует
  распределение по разделам при перелистывании; это не снимок всех данных БД.
- Общие счётчики показывают объём разделов, а подпись диапазона объясняет, что раздел
  может продолжиться на следующей странице. Сервер корректирует выход за последнюю страницу.
- Обновление после возвращения во вкладку ожидает реального завершения запроса;
  одновременные события focus/online/visibility не создают параллельные poll-запросы.
- Контракт и границы фильтрации описаны в backend `docs/calendar-api.md`.

## Корзина и публикация

- В разделах записей и медиатеки добавлена корзина: серверный поиск, страницы,
  подтверждение восстановления, понятная ошибка зависимости и переход к проверке записи.
- Восстановление сохраняет ID и возвращает запись скрытой. Матч получает `active=false`
  и `featured=false`; фотография остаётся приватной. Публикация выполняется явно.
- Удалённые связанные записи автоматически не возвращаются. Для фотографий проверяется
  наличие файла. При восстановлении турнира связанные матчи снимаются с публикации.
- Восстановление требует редакционной роли, CSRF и версии записи; операция и аудит
  выполняются в одной транзакции. Повторный запрос не скрывает уже опубликованный результат.
- Закрыт найденный OpenCode обход: нельзя создавать или переносить активных игроков,
  достижения и матчи под скрытую команду или турнир. Для нового назначения зала также
  требуется опубликованный зал. Проверяется итоговая публикация при PATCH, даже если
  поле `active` не передано. Черновики под скрытыми родителями допустимы.
- По выбранному владельцем сценарию скрытие/удаление зала сохраняет публичные матчи,
  но исключает из всех публичных ответов `venue` и `venue_id`: название, адрес,
  координаты и описание зала недоступны. В админке связь сохраняется, форму можно
  редактировать без замены прежнего зала. Восстановление зала не скрывает матчи;
  сведения о нём возвращаются только после его отдельной публикации.
- Миграция backend `0018_match_publication` добавляет независимую публикацию матчей.
  Подробный контракт — backend `docs/editor-api.md`.

## Публичный HTML

- `npm run build:prerender` создаёт отдельный `dist-prerender`: содержательные HTML,
  уникальные метаданные, canonical, Open Graph/Twitter, sitemap и robots. Помимо восьми
  основных страниц обнаруживаются опубликованные клубные профили и текущие заявки АСБ.
- Сборщик обращается только к разрешённым публичным GET API без cookies/авторизации.
  Админка получает отдельный shell с `noindex`; неизвестные маршруты — `spa.html`.
- Готовность определяется завершением загрузчиков Vue и обновлением DOM. Ошибки API,
  неполная пагинация и ошибки JavaScript останавливают сборку с сохранением предыдущего
  полного артефакта. Зависимости не добавлялись.
- Это статические снимки на момент сборки. После изменения публикации нужен rebuild;
  для календаря требуется расписание сборок в CI. Клиент Vue обновляет данные через API.
  SSR-гидрация и JSON-LD в этот результат не входят.
- Инструкция и переменные окружения находятся в README; Nginx-пример поддерживает
  готовые HTML, приватный shell и fallback. Реальный домен и сертификаты задаются при развёртывании.

  индексируется только подтверждённый опубликованный профиль. Проверены смена ID,

  меняется только после явного подтверждения редактора.
