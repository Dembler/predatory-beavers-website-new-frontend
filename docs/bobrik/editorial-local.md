# Локальная колонка Бобрика

Редактор доступен в изолированном dev-профиле: <http://127.0.0.1:5176/admin?tab=editorial>.
Нужна обычная учётная запись редактора или администратора. Флаг
`VITE_MASCOT_ENABLED=true` включает редактор вместе с чатом только при `import.meta.env.DEV`.
В production-сборку компоненты редактора и чата не входят.

`scripts/bobrik-local.ps1` запускает API, чат, отдельный `editorial-worker` и frontend.
Публичные страницы `/news`, `/news/{slug}` и `/news/rss.xml` обслуживает backend.
Ссылки на них — обычные HTML-ссылки; переход не перехватывает Vue Router.
Локальный Vite перенаправляет `/news` на изолированный API.

## Путь редактора

1. Выбрать понедельник нужной недели, команду, дисциплину и пожелания.
2. Нажать «Подготовить черновик». Опрос состояния читает уже созданное задание;
   он не запускает новую генерацию. Подготовку можно остановить.
3. Открыть готовую версию, сверить подтверждённые факты, оговорки и источники.
   Фактические предложения выбираются отдельно и публикуются дословно.
4. Сохранить правки новой версией, проверить её и прочитать замечания.
5. Одобрить сохранённую проверенную версию, затем опубликовать её отдельной кнопкой.
   Изменение текста снимает предыдущее одобрение. Снятие с публикации адресует
   именно опубликованную версию, даже если редактор открыл более новый черновик.

Новая генерация не заменяет открытые несохранённые правки. При сетевой ошибке,
истечении сессии или конфликте версии текст и пожелания остаются в форме этой вкладки.
Поздний ответ сохранения тоже не затирает текст, набранный после отправки.
Если ответ на создание задания потерялся, подтверждение повторяет исходный
Idempotency-Key и исходные пожелания. Автоматической повторной платной генерации нет.
Состояние формы хранится в памяти вкладки; закрытие вкладки не является сохранением.

Этапы подготовки ответа чата открываются по одному с интервалом 900 мс,
включая доставку нескольких SSE-событий сразу. Интервал действует и при reduced motion,
а анимация при этой настройке выключена. Готовый ответ, ошибка и отмена сразу
завершают очередь отображения. История содержит только реальные полученные этапы.

## Проверки интерфейса

```powershell
$env:E2E_MASCOT_ENABLED = 'true'
$env:E2E_BASE_URL = 'http://127.0.0.1:5176'
npx.cmd playwright test editorial.spec.ts mascot.spec.ts
node --test scripts/editorial.test.mjs scripts/mascot-progress.test.mjs
npm.cmd run build
```

Playwright полностью заменяет API и модель заглушками. Он проверяет выпуск точной
одобренной версии, сохранность правок, 401/409, потерянную отправку, отмену,
ошибку опроса, безопасный вывод текста и ссылок, desktop/mobile и последовательность
этапов при burst/replay. Проверки реальных генераций описаны отдельно в backend-отчёте;
браузерные заглушки не оценивают качество модели.

Локальные снимки интерфейса: `.data/bobrik-editorial-final/test-results/`.
