## Принятые решения

Первый публичный запуск объединяет новый 2D Бобрик в клубном стиле, чат по всей сохранённой истории клуба и подготовку черновиков превью/разборов. Публикация только через редактора; 3D позже. Денежный потолок приложения пока выключен (`unlimited`), сохраняются учёт расходов и технические token/timeout/retry/concurrency/rate limits.

В начале плана есть краткая карта реализации; дальше — данные, API, восстановление чата и задач, ревизии/фактчек публикаций, frontend и проверяемые gates запуска. Сам документ является спецификацией будущей реализации: присутствие плана в ветке не означает, что описанный продукт уже реализован или прошёл нагрузочные проверки.

## Что именно перенесено из Codex

`reference-pet/bars-up/pet.json` и `spritesheet.webp` скопированы из локального пакета питомца без изменений. Bars Up — баскетбольный снежный барс. Это референс и переносимый исходный арт; финальный Бобрик по плану создаётся отдельно в клубном стиле.

WebP — **статичный прозрачный атлас**, а не готовый анимированный WebP и не 3D-модель. В нём 8 столбцов и 9 строк, ячейка 192×208 px, общий размер 1536×1872 px. Анимацию создаёт проигрыватель, переключая кадры. Для воспроизведения готового арта не нужны Codex, LLM или доступ к API OpenAI.

`animation.json` подготовлен для переноса: он описывает координаты, число используемых кадров и интервалы. Этот файл не является оригинальным файлом пакета Codex. Idle отражает замедленный цикл установленного проигрывателя; остальные интервалы сохранены по контракту рядов. Поведение hover, повторов и переходов задаёт будущий проигрыватель сайта.

| Ряд, начиная с 0 | Клип | Кадров |
|---:|---|---:|
| 0 | idle | 6 |
| 1 | running-right | 8 |
| 2 | running-left | 8 |
| 3 | waving | 4 |
| 4 | jumping | 5 |
| 5 | failed | 8 |
| 6 | waiting | 6 |
| 7 | running | 6 |
| 8 | review | 6 |

Неиспользуемые ячейки прозрачны. Формула координат кадра: x = column × 192, y = row × 208. Поддерживаемые клипы этого референса не следует путать с обязательными состояниями будущего Бобрика: adapter/новый арт должен сопоставить их явно.

Размер изображения — 2 170 508 байт (около 2,17 МБ), исходного pet.json — 228 байт. Декодированная RGBA-картинка занимает 11 501 568 байт, около 10,97 МиБ, без дополнительных расходов браузера/GPU. Эти размеры относятся к референсу, а не обещают будущий бюджет нового арта.

## Проверка исходных файлов

SHA256 spritesheet.webp:

```text
6c19b3f10d9b6d26066e35f394b3999c725c9a6e55f90744b90305379930e9ce
```

Изображение и manifest должны проверяться на согласованность размеров, диапазона кадров и длительностей перед подключением. Оригинальный пакет оставлен самостоятельным: его можно скопировать обратно в каталог pets поддерживающей этот формат версии Codex. Изменять родные файлы для встраивания в текущую страницу не требуется.
