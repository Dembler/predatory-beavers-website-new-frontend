# Локальная разработка Бобрика

Ветка `codex/bobrik-plan-and-mascot-20261116`, база плана — `1d4022b`.
Это внутренний прототип первого среза, а не приёмка публичного MVP из
[плана](./bobrik-agent-plan.md). Для Бобрика владелец передал два PNG:
с мячом и поднятым большим пальцем. Канонический облик — вариант с мячом,
университетской формой ВГУ и номером 100. После ошибки API о нехватке кредитов
владелец выбрал локальное редактирование готовых PNG. Требования и происхождение
графики сохранены в [задании](./mascot-art-brief.md); исходный Bars Up сохраняется отдельно.

## Запуск на Windows

Из корня frontend:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/bobrik-local.ps1
```

- Сайт: <http://127.0.0.1:5176>.
- API: <http://127.0.0.1:8001/docs>.
- Фоновые процессы запускаются без дополнительных окон.
- Остановка: `powershell -File scripts/bobrik-local.ps1 -Stop`.
- Логи и PID: `.data/bobrik-local/`.

Уже работающие порты 5173/5174/5175/8000 не используются. `scripts/bobrik_local.py init`
однократно создаёт SQLite backup `data/local.db` в `data/bobrik-local.db`,
затем применяет миграции только к копии. Повторный запуск сохраняет копию и чат.
Исходная БД, `.env` и `.env.render` не изменяются. Спортивная синхронизация
в тестовом процессе отключена.

Для запуска отдельных процессов из backend:

```powershell
.venv/Scripts/python.exe scripts/bobrik_local.py init
.venv/Scripts/python.exe scripts/bobrik_local.py api
# В другом терминале:
.venv/Scripts/python.exe scripts/bobrik_local.py worker
# Ещё в одном терминале, для колонки:
.venv/Scripts/python.exe scripts/bobrik_local.py editorial-worker
```

Frontend отдельно:

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:8001'
$env:VITE_MASCOT_ENABLED = 'true'
npm run dev -- --host 127.0.0.1 --port 5176 --strictPort
```

## Платная модель

По решению владельца используется платный `deepseek-v4.1-flash` через подписку
OpenCode Go. Серверные параметры — в игнорируемом Git файле backend `.env.bobrik`;
шаблон — backend `.env.bobrik.example`. Ключ не относится к `VITE_*` и не
попадает во frontend. Обычный `.env` не загружается этим профилем.

Совместимый endpoint Go:
`https://opencode.ai/inference/go/openai/v1/chat/completions`.
Источник контракта: [официальная документация](https://opencode.ai/docs/console/harnesses).
Запросы содержат собственный User-Agent приложения и стабильный
`x-opencode-session`. Проверка 16 ноября 2026 вернула HTTP 200,
`model=deepseek-v4.1-flash`, `usage.opencode.billing_source=go`.
Автоматического перехода на другую модель или провайдера нет.

`budget_mode=unlimited` означает отсутствие денежного потолка приложения.
Ограничения длины, времени, частоты и выходных токенов сохраняются.

## Границы среза

- Независимый проигрыватель переданного 2D-атласа. На страницах — только персонаж
  с прозрачным фоном, без постоянной подписи. Во время прокрутки он двигается
  в зависимости от направления, через 180 мс после остановки замирает.
  При reduced motion остаётся неподвижным. Атлас загружается при первой
  прокрутке или открытии чата.
- При первом появлении за сессию вкладки — приглашение «Привет! Пообщаемся?»
  на пять секунд; открытие чата убирает приглашение.
- В чате показаны этапы подготовки ответа, публичные найденные материалы
  и время выполнения. Это события рабочего процесса, не приватные
  рассуждения провайдера. Завершённые этапы можно развернуть рядом с ответом.
- Внутренний чат с анонимной cookie-сессией, CSRF, идемпотентными запросами,
  сохранёнными SSE-событиями и отдельным процессом обработки.
- Поиск по сохранённому публичному материалу клуба без обращений к спортивным
  API во время ответа. Простая проверка ссылок и цифровых фактов не заменяет
  полный claims/groundedness gate из плана.
- Доступ только в dev/test; виджет включается флагом и отсутствует в production.

Далее по плану: канонические игры и неизменяемые analytics revisions,
PostgreSQL FTS, полноценные claims/evals, редакторские preview/recap drafts,
публикация через ревизии, usage dashboard и эксплуатационные проверки.
Анимация и этот чат сами по себе не являются готовым публичным MVP.

## Команда OpenCode

Две отдельные сессии `opencode-go/deepseek-v4-pro`: backend и frontend.
Backend подготовлен сессией OpenCode; frontend после разведки сессии реализован
основным разработчиком. Интеграция, исправления и финальная проверка выполняются
основным разработчиком. Сырые локальные журналы сессий хранятся в
`.data/bobrik-team/`, в Git не добавляются.

## Проверки 16 ноября 2026

44 backend-теста, 22 браузерные проверки desktop/mobile и 3 проверки редуктора
этапов подготовки прошли.

- Реальный вопрос об истории клуба: DeepSeek Flash через Go, сохранённый ответ
  с источниками, фактические токены и метаданные Go. Повторный POST вернул тот же run.
- Реальный браузер → API → worker: приветствие на компьютере и телефоне.
- API/worker/gateway: владение сессией, CSRF, идемпотентность, журнал событий,
  конкурентный захват, отмена, срок ожидания, сохранение расхода и отсутствие повторных вызовов.
- Playwright: lazy atlas, reduced motion, мобильная навигация, фокус, черновики,
  прозрачный launcher, приглашение на пять секунд, движение при прокрутке,
  безопасный текст/ссылки, SSE replay, восстановление после сетевых ошибок
  и сохранение этапов рядом с двумя последовательными ответами.
  Модель в этих тестах заменена заглушками.
- Сборка, TypeScript, ESLint, Ruff, Mypy и размеры атласа проверены.
- В production нет компонента чата и запросов к mascot API/атласу.
- Миграция 0022 проверена в обе стороны на временной копии БД с сохранением контента.
