# Agent workflow для Codex

Переносимая система разработки:

```text
grill-with-docs → to-spec → to-tickets → implement → code-review
      ↑             ↑           ↑          ↑            │
      └──────── возврат к затронутому этапу ────────────────┘
```

Шесть навыков: пять этапов и координатор `agent-workflow`. Шесть дополнительных
ролей подключаются по необходимости. Локальная программа на Python хранит состояние,
проверяет зависимости задач и свежесть результатов. Модели запускает сам Codex;
программа не обращается к API, не требует ключей и не является отдельным сервисом.

## Установка

Требуется Python 3.11+. Из каталога пакета:

```powershell
python install.py --dry-run
python install.py
```

Установщик использует `$CODEX_HOME`, а если переменная не задана — `~/.codex`.
Навыки размещаются в `skills`, роли — в `agents`. Этот путь навыков поддерживается
проверенной локальной версией Codex; актуальная документация также описывает
`~/.agents/skills`. Не устанавливайте одинаковые навыки одновременно в оба каталога.

Существующий `config.toml`, модель, провайдер, ключи, проектные инструкции и роли
других систем не изменяются. При неизвестном совпадении имён установка останавливается
до записи. Обновление учитывает контрольные суммы; пользовательские изменения
установленных файлов не перезаписываются. `--target PATH` задаёт отдельный Codex home
для проверки или другой установки. `--uninstall` удаляет только неизменённые файлы,
учтённые манифестом установки.

Начните новый разговор Codex, чтобы проверить обнаружение всех ролей и навыков.
Установка файлов и фактический запуск роли — разные проверки.

Проверить обнаружение навыков и формат установленных ролей без модельного запроса:

```powershell
python verify_install.py --workspace <путь-к-проекту>
```

Команда запускает локальный `codex app-server` с временным профилем, добавляет
установленные навыки через `skills/extraRoots/set` и проверяет их через `skills/list`.
Профиль Codex создаётся во временном каталоге; модельные запросы не выполняются.
Проверка файлов ролей не доказывает обновление ролей в уже открытом разговоре.

## Использование

В Codex:

```text
$agent-workflow Реализуй <задачу> в <проекте>.
```

Координатор исследует задачу, фиксирует спецификацию, создаёт локальные тикеты,
организует реализацию, проверки и независимое ревью. Между этапами не требуется
дополнительное согласие, если оно не нужно для конкретного действия или решения.
Публикация, отправка сообщений, push и deployment не входят в эту команду автоматически.

Отдельные этапы можно вызывать самостоятельно:

```text
$grill-with-docs Разбери требования к <изменению> по коду и документации.
$to-spec Подготовь спецификацию по текущим требованиям.
$to-tickets Разложи текущую спецификацию на задачи.
$implement Выполни готовые задачи текущего запуска.
$code-review Проверь текущую реализацию по спецификации и результатам проверок.
```

Для продолжения укажите путь к существующему запуску:

```text
$agent-workflow Продолжи запуск из <путь к каталогу запуска>.
```

Режим `light` сохраняет краткие документы и обычно один тикет. `standard` и `full`
позволяют выделить исследования, архитектуру и QA в отдельные задачи. Все режимы
сохраняют условия готовности; число агентов выбирается по работе.

## Механизм выполнения

[Справочник команд и JSON](skills/agent-workflow/references/runtime.md) описывает
исполняемую часть. Запуск создаётся с явными путями к рабочему каталогу и исходным
файлам; состояние хранится отдельно от изменяемого кода.

- Артефакты этапов и граф задач сохраняются атомарно.
- Задача требует завершённых и актуальных зависимостей; пересекающиеся области
  редактирования не выдаются двум исполнителям одновременно.
- Проверки запускаются явной командой без shell и сериализуются для общего workspace.
- Проверки и одобрения содержат снимок выбранных исходных файлов. Изменение кода
  делает старые доказательства недостаточными для завершения.
- Финальные проверки выполняются на объединённом состоянии, затем проводится
  финальное независимое ревью и вызывается `complete`.
- Замечания возвращают задачу исполнителю. Повторные отказы требуют явной
  переоценки плана; более ранний этап можно открыть с записанной причиной.

Ограничения: независимость агента проверяется по заявленным идентификаторам, поэтому
координатор обязан передавать настоящие ID запущенных агентов. Снимок охватывает
только объявленные пути: нужные зависимости и конфигурацию следует включить в scope.
Программа не определяет смысловую достаточность теста и не доказывает, что браузер
или production действительно проверены. Эти результаты требуют отдельного наблюдения.
Роли с инструкцией read-only наследуют разрешения родителя; сам файл роли не создаёт
дополнительную системную песочницу.

## Проверка пакета

Для полного набора тестов нужен `pytest`:

```powershell
python -m pytest tests -q -p no:cacheprovider
```

Тесты используют временные каталоги и не устанавливают пакет в пользовательское
окружение. Сам runtime и установщик используют только стандартную библиотеку.
Протокол фактической проверки этой версии — [VERIFICATION.md](VERIFICATION.md).

Структура пакета:

```text
codex-workflow/
├── agents/                 дополнительные роли Codex
├── skills/                 пять этапов и координатор с runtime
├── tests/                  проверки состояния и установщика
├── install.py              добавочная установка и удаление
└── README.md
```

Форматы сверены с официальной документацией
[навыков](https://learn.chatgpt.com/docs/build-skills) и
[агентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).
